客户日常操作

初始化、导入、续期与恢复怎么做

按角色分工：我方制作并签发 → 客户运维初始化与入网 → 管理员导入/恢复 → 各服务独立运行。下列命令只作说明，本页不会执行。

首次安装流程

我方构建固定公钥、模式和清单，预装依赖
→
客户初始化同安装 UUID / service.key；两端各自 clock
→
取得机器码文件可出网则导出，不能则抄 IC1
→
我方商业签发合同决定绑定及期限
→
文件入网并导入Metor 本地预检、CAS、原子发布
首次部署示例；保留目录，重装/换机按既定规则重新签发
# 在独立安装根目录；这是首次安装准备，不是时间异常修复命令
sudo python3 deployment/scripts/local-stack.py license-init \
  --license-root /opt/icp-diag/runtime/license

实际物理文件及挂载

默认 Compose 约定；文件锁是运行辅助，备份时排除
宿主 LICENSE_ROOT/                    服务内 /run/icp-license/
  identity/installation.json          identity/installation.json  两服务只读
  identity/service.key               identity/service.key         两服务只读
  shared/active.license.json          shared/active.license.json   Metor 可写 / AI 只读
  state/metor/clock.json              state/metor/clock.json       仅 Metor 可写
  state/metor/clock.json.lock         Metor 文件锁
  state/metor/recovery-challenge.json Metor 按需持久挑战
  state/ai/clock.json                 state/ai/clock.json          仅 AI 可写
  state/ai/clock.lock                 AI 文件锁
  state/ai/recovery-challenge.json    AI 按需持久挑战

宿主 machine-id（不是容器临时生成值）
  → /run/icp-host/machine-id          两服务只读，HOST_INSTALL 才需使用

授权目录由安装器设置数值权限：共同读取组 21000，Metor 21001、AI 21002。缺少可读宿主标识不自动伪造；我方签发的 UNBOUND 可以不读 machine-id，但仍需要 identity/service.key 和时间状态。

“导入”到底做了什么？

浏览器选文件文件入网，不代表已安装
→
Metor 管理 API验签/产品/绑定/当前期限 + 当前文件摘要 CAS
→
原子保存替换共享 active.license.json
→
两端观察各自读取新商业文件并校验；无需联动确认

推荐通过管理员页面导入，不把恢复文件 copy 成 active.license.json。直接复制文件没有 API 的候选预检和并发保护，写入半文件还会被 SDK 视为异常；共享目录只是保存结果的位置。

管理员页面操作

  1. 真实模式用平台管理员登录，进入设置 → 软件授权（/platform/settings/license）。
  2. 点击取得机器码或下载授权申请；把资料交我方，等待商业许可文件入网。机器标识异常时可联系我方明确签 UNBOUND。
  3. 核对当前状态和 SHA256，选择商业许可文件并导入。APPLIED 后刷新并查看本服务实际状态。
  4. 收到摘要冲突或未知结果时，保留文件、刷新核对，再决定是否明确重试；不要反复盲点导入。

续期和时间恢复，不要选错入口

当前问题处理路径不应做的事
EXPIRED / 合同期结束我方新签商业许可 → 商业导入用恢复文件延长商业期限
NOT_YET_VALID核对 UTC 和签名生效日直接改商业文件时间
CLOCK_ROLLBACK / CLOCK_STATE_INVALID校正 UTC → 本服务申请 → 我方恢复签发 → 本服务应用删 clock / 重建安装来绕过
POLICY_INVALID恢复正确发行资源并重启服务靠续期或恢复文件修复清单
身份/主密钥损坏按安装资料备份和既定重签规则处理把它当作普通时间恢复

一个服务恢复，另一个会怎样？

只恢复 Metor

Metor 的 clock / 内存基准改变，AI state/ai 不改变。若 AI 无异常，不需要操作。

两个服务都异常

分别取得对应申请、签发和应用。当前方案没有统一双端恢复文件或自动协调器。

Metor 在页面取得申请、复制完整手抄资料、导入恢复文件；AI 使用上一页的 local-stack 运维命令。恢复申请交 issuer 时只保存 data 对象；202 的未知响应不是可用申请。
