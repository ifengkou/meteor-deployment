Metor 集成与运行

Java 装配、过滤器、关键入口与管理 API

Metor = 产品级发行资料与策略 + 通用 Java SDK。平台过滤器不写死 aerospace API，应用清单和固定方法各自负责范围。

我方构建接入步骤

  1. 将最终 SDK 0.6.0 Maven 发行输入放到 metor-service/vendor/license-maven，或显式指定 licenseMavenRepository。
  2. 将审核过的公钥信任作为 trust.json 构建输入，不能放商业私钥。
  3. 在 META-INF/metor-license-routes.json 维护应用 API 清单；构建固定其原始字节 SHA256。
  4. 用 CUSTOMER_REQUIRED 构建客户 BootJar/镜像；普通 check bootJar 默认生成 DEVELOPMENT 元数据。
  5. 交付前准备安装目录和挂载，验证当前产品全部 Java 运行依赖已装入 BootJar。
构建示例；正式客户信任输入与最终 Linux 验收另行准备
# 在 metor-service 根目录，使用已准备的受控构建输入
./gradlew customerBootJar \
  -PlicenseCustomerTrust=/absolute/vendor/metor-trust.json

# 隔离离线开发验证；这个命令默认是 DEVELOPMENT 构建
./gradlew check bootJar --offline \
  -PlicenseMavenRepository=/absolute/vendor/license-maven

启动装配树

当前调用树与文件归属
LicenseConfiguration
  LicenseReleaseMetadata.load
    META-INF/metor-license-release.json
      CUSTOMER_REQUIRED + trusted_keys + api_routes_sha256
  LicenseHttpProperties.load
    META-INF/metor-license-routes.json
      校验摘要 / 严格规则 → 内存不可变策略
  MetorLicenseService
    一个 LicenseRuntime(service="metor", recoveryPrefix="RC1J")
    guard：先校验产品策略，再委托 Runtime
  LicenseManagementService
    本地状态、机器申请、商业文件 CAS / 原子发布、恢复委托
  LicenseRequestFilter + TicketService
    注入同一个产品 guard
  checkpoint：每 30 秒

一个创建请求经过哪些层？

原账号/角色权限原安全链继续生效
→
LicenseRequestFilter只匹配产品包内规则
→
MetorLicenseService策略有效？本地 Runtime 允许？
→
TicketService.create首行固定 guard；随后原业务

固定方法检查覆盖绕过 HTTP 的直接调用。进入业务后不增加授权任务字段、执行令牌、队列/重试控制或数据库迁移。健康正常不表示许可有效，授权失败通常保持服务运行并返回受控 403。
