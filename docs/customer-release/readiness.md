# 发布检查清单

每次发行按以下清单检查，并将版本、摘要和验收结果保存到独立发行记录。

## 1. 目标环境

- [ ] 确认客户 CPU 为 Linux x86_64／AMD64，四个镜像均为 linux/amd64。
- [ ] 确认 Linux 发行版、CPU／内存／磁盘容量、时钟同步、联网策略、访问入口与防火墙规则。
- [ ] 确认 Docker 24.0.7、Python 3.8.10 及包内独立 Compose 2.33.0 的运行条件。
- [ ] 确认域名、证书、代理配置和交付验收范围。

## 2. 构建输入

- [ ] 分别冻结并推送 ai-runtime-service、metor-service、frontend、deployment 的发布提交，保存完整 SHA。
- [ ] 使用干净工作区和唯一版本号构建。
- [ ] 校验正式 SDK 0.7.1 制品和发行摘要。
- [ ] 两端使用同一份 Issuer 公开配置，核对产品、服务、协议参数、公钥与签发环境一致。
- [ ] 准备完整 Embedding、构建依赖和固定版本 Compose 二进制。

具体命令见 [build](01-build.md)。

## 3. 交付包

- [ ] 四镜像实际架构均为 linux/amd64，SDK 载荷和 CUSTOMER_REQUIRED 模式检查通过。
- [ ] 镜像内公开配置摘要与本次输入一致。
- [ ] 使用统一 export 生成 tar.gz、manifest、SHA256SUMS 和外层 .sha256。
- [ ] 包内完整 Embedding 已通过本次 AI 镜像的断网加载与编码检查。
- [ ] 包内只包含约定凭据和五份客户使用指南，不含源码、业务数据、安装身份或签发私钥。
- [ ] 解压、内部校验、导入及实际镜像 ID／架构核对通过。

## 4. 部署与授权

- [ ] 按 [deploy](02-deploy.md)完成首次目录准备、单独 license-init、数据库迁移和服务启动。
- [ ] 核对数值权限、挂载读写范围、四服务健康、客户访问入口和管理员登录。
- [ ] 按 [签发](03-license-issue.md)及 [导入](04-license-import.md)完成许可签发、导入、重复导入和状态核对。
- [ ] Metor／AI 各自 ACTIVE，普通用户权限和受控操作符合约定。
- [ ] 服务重启与离线运行后，安装身份、许可及业务数据保持可用。

## 5. 业务验收

- [ ] 按 [资料清单](business-materials.md)准备 Chat 服务、六场景、规则、知识库／图谱和客户账号。
- [ ] 在原生 Linux AMD64 使用获准真实 DAT／ZIP 完成 JNI 解密、解析、事件入库和结果对账。
- [ ] 完成故障、巡检、报告、原始文件及导出验收。
- [ ] 完成真实模型调用与知识库检索，核对业务结果。
- [ ] 按 [授权页面清单](../../../frontend/docs/acceptance/software-license.md)完成人工页面验收。

## 6. 运维与交付确认

- [ ] 完成一致性备份、同宿主隔离空目标恢复和业务对账。
- [ ] 验证升级和兼容回退，保持原安装身份及最新时间记录。
- [ ] 指定运维联系人、备份保管位置和证书续期负责人。
- [ ] 交付负责人确认范围、验收结果和客户资料完整。

发行记录保存版本号、目标平台、四仓 SHA、SDK／公开配置摘要、四镜像 ID、工具镜像 ID、包与模型摘要、迁移版本、业务配置版本、入口方案、验收执行人及结果。凭据和客户原始样本单独保管。
