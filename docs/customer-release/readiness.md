## 前端上游 DNS 缓存缺陷（2026-10-27）

本机 `icp-diag-local` 出现 API 502：Nginx 仍连接 `172.28.0.2:8080`，但 Metor 当前地址为 `172.28.0.5`，容器内直连服务名返回 200。旧模板 `proxy_pass http://${JAVA_UPSTREAM}` 仅在启动／重载时解析地址，后端重建导致 IP 变化后可能持续失败；前端 `/healthz` 不检查代理依赖，因此仍可显示 healthy。

已核对 `candidate-20261026-2` 与 `candidate-20261027-1` 的 manifest：两者均引用 `metor-platform-frontend:amd64-candidate-20261026-1`（镜像 ID `sha256:86f837e8b3345baef307a7582fb3c299a406f486360495e186e3442579a59a99`）。实际读取该镜像模板确认包含旧配置，ARM64 验证镜像亦相同。两份既有候选归档均受此缺陷影响，不能以此前整栈停启通过视为已覆盖后端单独重建。

前端源码已改用 Docker DNS `127.0.0.11`、10 秒缓存及共享 upstream 的 `resolve`。本机 18180 已切换到基于原运行镜像、仅替换路由模板的 `metor-platform-frontend:release-20261019-2dd1820-dnsfix-20261027`，接口复测 200。隔离 Docker 网络中后端 IP 从 `.10` 改为 `.20`、不重启前端，约 11 秒自动恢复；路径／查询参数、AI actor 头移除、HTML 导航及未知 API 404 均通过，临时容器与网络已清理。

**现有交付归档尚未重打包。** 正式交付前须将修复纳入对应架构前端镜像，使用新版本号重新导出候选包和摘要，并补验后端单独重建后的自动恢复；本机 ARM64 修复不替代 AMD64 发布验证。
